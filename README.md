# 泡泡陪伴

桌宠 / 桌娘的「眼睛和脑子」遥控器。

装好之后，在聊天里跟机器人说一句，就能控制她怎么陪你看东西：

```
陪伴                 看当前状态
陪伴 医生            逐项体检（Key / TTS / 转写 / OCR / 字幕 / 帧缓冲 / 弹幕）
陪伴 模式 anime      切模式：auto normal video anime live course game off
陪伴 说 我在看呢      让她立刻说一句（走你配的本地 TTS）
陪伴 摘要            立刻整理一次识屏摘要
陪伴 弹幕 开         直播弹幕开关（不带参数=看状态）
陪伴 弹幕出声 关      回弹幕只冒泡、不念（不带参数=看状态）
陪伴 启动            拉起核心服务（需要先配 start_script）
```

还有一条：**随口说「看一眼屏幕」就行**，不用记固定命令：

```
看看屏幕 / 看下屏幕 / 帮我看一下我的屏幕 / 你帮我瞧瞧桌面
屏幕上有什么 / 桌面显示什么 / look at my screen
```

它只认「看 + 屏幕/桌面/画面/显示器」这种组合，不会把「帮我看看这个报错」误当成看屏幕。

## 它是怎么分工的

- **核心**：一个本地常驻服务（默认 `http://127.0.0.1:9888`），负责截屏、帧拼图、
  字幕 OCR、音频转写、TTS、模式状态。它自己起、自己重启。
- **这个插件**：只管控制面——发 HTTP 给核心，把结果显示在聊天里。

这样分工的好处：聊天机器人重启不影响采集；核心崩了不拖累机器人；插件随时能升级。

> 核心不在这个仓库里。它是配套的本地服务，接口约定见
> [`README-FOR-AI.md`](README-FOR-AI.md)。
> 核心网关是开源的：<https://github.com/zuoyu123654/paopao-pet-gateway>（克隆后跑 `install.ps1`）。按里面的
> `README-FOR-AI.md` 装：建 venv、填 API Key、把桌宠的 `base_url` 指到
> `http://127.0.0.1:9888` 即可。

## 模式

| 模式 | 什么时候用 | 她的信息来源 |
|---|---|---|
| `auto` | 默认，自动判断 | 按前台窗口推断 |
| `normal` | 日常 | 帧拼图 + 同 App 近况 |
| `video` | 普通投稿视频 | 字幕优先（bili CLI），OCR 兜底 |
| `anime` | 番剧 | 字幕条 OCR + 集号 + 热评；角色叫简称 |
| `live` | 直播 | 主播说的（音频转写）+ 弹幕（开了直播弹幕才回） |
| `course` | 网课 | 网课老师说的（音频转写）+ PPT 帧 |
| `game` | 打游戏 | 画面 + 操作，不吃字幕、不指挥 |
| `off` | 别出声 | 只记账，不念识屏 |

> 「直播弹幕」是**叠加层**，不是模式：和上面任何模式同时开。勾「回弹幕出声」= 念出来，
> 不勾 = 只在头顶气泡里回。

## 安装

1. 插件目录放到 `<AstrBot>/data/plugins/astrbot_plugin_paopao_companion/`
2. WebUI → 插件 → 点一下「重载」
3. 发 `陪伴 医生`，全绿就算好了

依赖：`httpx`（已在 `requirements.txt`）。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `gateway_url` | `http://127.0.0.1:9888` | 核心服务地址 |
| `start_script` | 空 | 核心启动脚本（可选，留空就不自动起） |
| `auto_start` | `false` | 插件加载时是否自动拉起核心 |
| `timeout_seconds` | `12` | HTTP 超时 |

## 边界

- 这个插件不采集、不截屏、不转写，只发 HTTP。
- 没有核心服务时，命令会回「核心没响应」，不会报错崩溃。
- 核心必须跑在**用户桌面会话**里（截屏和音频环回需要桌面），别做成系统服务。
